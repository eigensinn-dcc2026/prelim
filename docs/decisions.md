## 2026-09-23 — [M2] 제출 우선순위 다시 L1로 — L2 추론 파이프라인 미비로 보류

## 2026-09-23 — [M2] L2(CNN) 공식 Validation 확정 — L1 대비 압도적 우위, 제출 우선순위 L2로 전환

- **현황**: 2026-09-18 결정("L1을 먼저 완성하고 L2는 잠정 보류")에서 걸어둔 완료 조건 4개
  — (1) hop-length 실험, (2) `mission2-l2-cnn-clean`에 라벨 수정 반영, (3) 공식 Validation 1회
  검증, (4) `main` 병합 여부 결정 — 중 (2)·(3)이 이번에 완료됨. (1)은 여전히 미평가.
- **결과**: L2(SpeakerCNNLarge, 라벨 수정 반영 재학습) 공식 Validation **90.88~90.89%**
  (M2-VAL-003) — 같은 시점 L1 최종 후보(M2-VAL-002, 86.44%) 대비 **+4.44~4.45%p**. 타 팀
  레포지토리 조사에서 확인된 최고 기록(eunkyo00, 90.25%)도 상회 — 현재 파악된 범위에서
  최고 기록.
- **인프라 메모**: 로컬 CPU 추론이 111,947발화 기준 비현실적으로 느려(개별 `.npy` 파일을
  OneDrive 동기화 폴더에서 하나씩 읽는 구조) Colab GPU로 전환. 같은 체크포인트(epoch 21)를
  CPU/GPU 양쪽에서 평가한 결과 정확도는 사실상 동일(90.89%/90.88%)하나 부동소수점 차이로
  약 250건(전체의 0.22%)의 개별 예측이 달라짐 — 결정 경계(대회 규정상 고정 0.5 threshold)
  부근 케이스로 추정, 결론에는 영향 없음.
- **결정**: (4) `main` 병합 여부를 지금 결정한다 — 제출 우선순위를 L2로 전환. L1(86.44%)은
  안정적인 대안/비교 baseline으로 유지하되, 이후 accuracy 개선 작업은 L2 트랙에 집중한다.
  (1) hop-length 실험은 이미 큰 격차가 확인된 상태라 급하지 않음 — 여력이 되면 추가 개선
  실험으로 낮은 우선순위 유지.
- **이유**: +4.4%p는 대회 채점(accuracy 단일 지표) 기준 매우 큰 차이이고, 2026-09-18 시점의
  "L1이 정리 비용이 낮다"는 판단 근거는 이제 L1이 완성된 상태이므로 더 이상 유효하지 않음.
  L2를 더 보류할수록 기회비용만 커짐(2026-09-18 결정에서 이미 지적된 리스크).
- **후속 조치**: `mission2-l2-cnn-clean`을 `main`에 병합(팀 리뷰 거쳐서, 셀프 머지 금지
  원칙 준수). L1 대비 L2가 어떤 유형의 오류를 더 고치는지/못 고치는지 per-utterance 비교 진행 중.
- **관련**: M2-VAL-002, M2-VAL-003, M2-CNN-003(`docs/experiment_log.md`),
  [`m2_l2_official_validation_result_local_cpu.json`](../reports/mission2/m2_l2_official_validation_result_local_cpu.json),

## 2026-09-20 — [M3] recordId 단위 층화 분할과 JSON 행 단위 층화 분할 비교 필요 (미결)

- **현황**: [`mission3_baseline.py`](../scripts/mission3_baseline.py)는 `recordId`로 그룹화한 뒤
  다중레이블 층화 분할하고, [`mission3_baseline 최종 수정본.py`](<../scripts/mission3_baseline 최종 수정본.py>)는
  JSON 행에 직접 다중레이블 층화 분할을 적용함.
- **문제**: 수정본은 `recordId`를 보존하지 않아 중복 `recordId`가 존재할 경우 같은 통화가
  train/validation에 함께 들어갈 수 있음. 반대로 모든 `recordId`가 고유하다면 0.3955와 0.4530의
  차이는 리키지가 아니라 서로 다른 표본 분할에 따른 변동일 수 있음.
- **함께 사라진 안전장치**: 원본은 분할 후 train/validation의 `recordId` overlap을 검사해
  0이 아니면 `RuntimeError`로 중단하지만, 수정본에는 이 검사가 없음. 지금 중복이 0이더라도 데이터가
  갱신되면 리키지가 조용히 유입될 수 있으므로 어느 쪽을 채택하든 overlap 검사는 유지할 것.
  수정본은 발화의 `startAt` 시간순 정렬도 제거했는데, TF-IDF 1~2gram 기준으로는 발화 경계
  bigram이 달라질 수 있음. unigram에는 영향이 없지만 현재 성능 영향의 크기는 미검증이며,
  순서에 의존하는 모델로 바꾸면 시간순 정렬을 반드시 복원해야 함.
- **결정**: 같은 데이터·모델·seed에서 전체 행 수, 고유 `recordId` 수, 중복 그룹 수와
  train/validation overlap을 기록하고 그룹 단위 분할로 재평가하기 전까지 0.4530을 최종 수치로 채택하지 않음.
- **담당/완료 조건**: 이수빈 확인 요청. 분할 감사 수치와 재실행 결과를 기계 판독 가능한 로그로 남기면 종결.

## 2026-09-18 — [M2] 채점 기준은 accuracy 단일 지표 — recall 격차 보정 실험 기각

- **현황**: 대원(0) recall이 신고자(1) recall보다 항상 8~9%p 낮은 구조적 비대칭을 줄이려
  threshold(0.5→0.75)·class_weight(1.0→3.0) 스윕을 시도. 대원 recall을 올리는 만큼 신고자
  recall이 대칭적으로 깎이고 전체 accuracy는 항상 손해(threshold=0.55: −0.20%p).

  줄이려는 조정은 전부 적용하지 않는다. 격차는 오류 분석용 참고 지표로만 계속 로깅한다.
- **이유**: 격차를 줄이는 방법을 실제로 찾았지만, 채점 기준상 accuracy를 깎으면서까지 쓸
  이유가 없음 — 데이터로 증명된 트레이드오프를 알고도 안 쓰는 것도 판단이다.

- **현황**: L2(Mel-spectrogram+CNN, SpeakerCNNLarge)가 내부 검증 91.22%로 L1(86.77%/86.40%)
  보다 정확도가 높음. 그러나 L2 작업 브랜치가 아직 실험 중이던 GBM 피처 브랜치 위에서 분기되어
  커밋이 뒤섞였던 프로세스 문제가 있었고(아래 브랜치 분기 항목 참조), L1은 이 시점까지 규정
  위반 피처가 안 걸러진 상태였음.
- **결정**: L2가 정확도는 더 높지만, L1 베이스라인부터 규정 준수·모델 비교·공식 검증까지
  제대로 완성하는 것을 먼저 하고 L2는 잠정 보류.
- **이유**: L1 정리 비용이 L2보다 낮고 빨랐음(모델 비교+튜닝+공식 검증이 하루 만에 완료). L2는

- **리스크**: L2(91.22%)가 L1(86.40%)보다 +4.82%p 높은데 제출 안 하면 점수 손해로 이어질 수
  있음 — 보류가 길어질수록 기회비용 증가. L2는 공식 Validation도 아직 미검증.
- **담당/완료 조건**: L2 재개 시 (1) hop-length 실험 재학습/평가, (2) `mission2-l2-cnn-clean`
  브랜치에 누락된 라벨 수정 반영, (3) 공식 Validation 1회 검증, (4) `main` 병합 여부 결정.
