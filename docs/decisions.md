## 2026-09-29 — [M2] ECAPA-TDNN 백본 1단계 파일럿 착수 — margin loss(AAM-softmax)는 2단계로 분리

- **배경**: 단일 CNN 개선 시도(위 M2-CNN-004~009, M2-AUG-001)가 전부 사전 기준을 통과하지 못해서,
  "구조를 아예 다른 계열로 바꾸면 어떨까"를 검토했다. 화자 인식 분야에서 쓰는 ECAPA-TDNN(시간축
  dilated conv + SE 게이트 + attentive statistics pooling) 구조와, 그 분야에서 흔히 같이 쓰는
  margin 기반 손실함수(AAM-softmax)를 후보로 정했다.
- **결정**: 두 가지를 한 번에 넣지 않고 2단계로 나눈다. 1단계는 구조(TDNN 백본)만 바꾸고 손실함수는
  그대로 softmax를 쓴다. 1단계가 기존 CNN 파일럿 기준을 통과할 때만, 그 위에 AAM-softmax를 추가하는
  2단계로 넘어간다.
- **이유**: AAM-softmax는 원래 화자가 수천 명인 문제(각 클래스를 각도상 멀리 떼어놓기)에서 쓰는
  기법이라, 우리처럼 클래스가 2개(대원/신고자)뿐인 문제에서는 효과가 작거나 없을 수 있다. 구조와
  손실함수를 한 번에 바꾸면 나중에 어느 쪽이 효과가 있었는지(또는 없었는지) 구분할 수 없다. 또한
  AAM-softmax는 학습 시 정답 라벨을 forward에 같이 넣어야 해서(정답 클래스에만 각도 마진을 주므로)
  기존 5개 CNN 모델이 공유하는 학습 루프(`train_one_epoch`/`evaluate`, `model(*inputs)` 계약)와 안
  맞는다 — 1단계에서 이득이 없으면 이 별도 학습 루프를 짜는 비용을 아낄 수 있다.
- **구현 메모**: `dcc_data/mission2_cnn.py`가 다른 세션에서 동시에(uncommitted) 수정 중이라, 그
  파일은 전혀 건드리지 않고 완전히 새 파일(`dcc_data/mission2_ecapa.py`)로 독립적으로 구현했다. 기존
  `SpectrogramDataset`과 공용 학습 루프는 그대로 재사용(가져오기만 함). 파라미터 수(~35만 개)는 기준
  `SpeakerCNNLarge`(42만 개)와 비슷한 규모로 맞춰서, 나중에 성능 차이가 나면 "파라미터가 더 많아서"가
  아니라 구조 자체 때문이라고 말할 수 있게 했다. 풀링 시 패딩 프레임은 각 발화의 실제 프레임 수로
  정확히 마스킹(다운샘플링 계산 없이 시간축 길이를 그대로 유지하는 구조라서 가능 — M2-CNN-009의
  근사 마스킹보다 더 정확함). BatchNorm 대신 GroupNorm을 써서, 배치 1개·프레임 1개짜리 극단적으로
  짧은 발화에서도 에러 없이 돌고, 학습 때 배치 통계와 실제 제출 추론(발화 하나씩) 때 쓰는 통계가
  갈라지는(M2-CNN-009가 고치려던 것과 같은 종류의) 문제도 원천적으로 피한다.
- **현재 상태(2026-09-29)**: 코드 작성 + CPU 스모크 테스트(10개, 패딩과 무관하게 결과가 똑같은지
  확인하는 테스트 포함) + 전체 테스트 스위트(423개) 통과 확인까지 완료. 아직 실제 파일럿 학습(Colab
  GPU)은 안 함. 브랜치 `gwanghee/mission2-l2-ecapa-tdnn`(`mission2-l2-cnn-clean` 기준으로 분기, 커밋
  `ff3d6d9`), 로컬 커밋만 있고 push는 안 함.
- **후속 조치**: 기존 3,000통화 파일럿 캐시로 `--torch-seed` 1/2/3 학습 → 기준(M2-CNN-007의 40-mel
  Large, seed당 88.6~88.9%) 대비 3 seed 전부 양수 & 평균 +0.5%p 이상이면 1단계 통과 → 전체 데이터
  (29,200통화) 승격 검토, 통과 못하면 2단계(AAM-softmax)는 생략하고 중단.

## 2026-09-29 — [M2] seed 앙상블 예비 확인 통과 — 전체 데이터로 CNN 2개 더 학습하기로 함 (현재 GPU 할당량으로 중단)

- **현황**: 단일 CNN 개선 시도(발화 길이 입력, hop/n_mels 해상도 확대, L1+L2 합치기, SpecAugment/SWA,
  ResNet, 마스크 풀링)가 전부 각자 사전 기준을 통과하지 못했다(이 문서의 관련 항목들 참조). 남은
  후보로, 같은 CNN을 seed만 바꿔 여러 개 학습해서 합치는(seed ensemble) 방법이 남아 있었다.
- **1단계(M2-ENS-002, 재학습 없음)**: 전체 데이터 재학습(GPU 몇 시간)에 들어가기 전에, 이미 있는
  M2-CNN-007 파일럿 체크포인트 3개만으로 먼저 신호가 있는지 쌌게 확인했다. 4개 조합(쌍 3개 + 세 개
  전부) 전부 양수(+0.31~+0.48%p)로, 실행 전 정한 진행 기준(3/4 이상 양수 AND 세 개 조합 +0.3%p
  이상)을 통과했다 — 이번 세션에서 부호가 전혀 안 갈린 유일한 결과였다.
- **결정**: 예비 신호가 있으므로 전체 데이터(29,200통화)로 CNN 2개(`--torch-seed 2`/`3`)를 추가
  학습해서 진짜 3모델 앙상블을 시험하기로 한다(M2-ENS-003). 최종 채택 여부는 M2-ENS-001과 같은
  내부 검증 통화 1,200개에서 **+0.5%p 이상**(파일럿의 진행 기준 +0.3%p보다 엄격한 최종 기준)을
  넘어야 하고, 그걸 넘어야만 공식 Validation에서 1회 확인한다. 실제 제출 스크립트에 앙상블을 넣는
  건 이 계획이 통과할 때만 진행할 별도 후속 작업이다.
- **이유**: 파일럿 규모 예비 확인은 재학습 없이 몇 분이면 끝나서, 몇 시간짜리 전체 데이터 학습을
  하기 전에 "이 방향이 가망이 있는지"를 싸게 걸러내는 용도다. 결과가 이번 세션에서 유일하게
  일관됐다는 점(부호가 안 갈림)도 계속할 근거로 봤다.
- **현재 상태(2026-09-29)**: **Colab Pro GPU 할당량이 소진되어 학습이 일시 중단**됐다. 모델 1개만
  먼저 학습하거나 Kaggle 등 다른 무료 GPU로 옮기는 대안도 있었지만, 할당량이 다시 찰 때까지
  기다리기로 했다. 아직 학습된 모델도, M2-ENS-003의 평가 결과도 없다.
- **후속 조치**: 할당량이 차면 준비된 Colab 스크립트를 그대로 재실행. 완료되면 내부 검증 1,200통화
  로 +0.5%p 기준 확인 → 통과 시 공식 Validation 1회 확인 → 통과 시 제출 스크립트에 앙상블 연결(별도
  작업)을 순서대로 진행.
- **관련**: M2-CNN-007, M2-ENS-001, M2-CNN-008, M2-CNN-009(`docs/experiment_log.md`),
  [`m2_seed_ensemble_pilot_check.md`](../reports/mission2/m2_seed_ensemble_pilot_check.md).

## 2026-09-29 — [M2] 모델 교체(ResNet / 마스크 풀링) 둘 다 기각 — "모델만 바꾸기" 방향도 채택 근거 못 얻음

- **현황**: 입력(40밴드 멜 이미지)은 그대로 두고 모델만 바꾸면 89.7% 벽을 넘을 수 있는지 확인했다
  (M2-CNN-008/009). 배경: 3단→4단 확대(`SpeakerCNN`→`SpeakerCNNLarge`)가 89.6%→91.22%(내부 검증)로
  올랐던 반면, 입력 해상도를 올리는 시도 세 가지(M2-CNN-004/005/007)는 모두 채택 근거를 못 얻었다.
  두 후보를 통화 3,000건 파일럿에서 `--torch-seed` 1/2/3, 각 35에폭으로 seed마다 처음부터 새로
  학습했다(기준 모델 large만 M2-CNN-007에서 같은 조건으로 이미 학습해 둔 체크포인트를 재사용):
  (1) resnet — 지름길 연결 + 작은 시작부, 파라미터 126만 개(기준의 약 3배). (2)
  large-masked — 기준과 파라미터 동일, 마지막 시간 평균에서 패딩 구간만 제외(학습과 평가 모두, 학습
  입력의 패딩은 배치 안 가장 긴 발화 기준 그대로). 판정은 제출 방식과
  같은 고립 평가(acc_isolated, 발화 하나씩·자기 자신만 300프레임 패딩)로, 배치 평가는 참고용으로만
  같이 냈다(300프레임 고정 패딩이 이미 +1.15%p를 회복시켰기 때문에, 배치 평가만 보면 그 몫을
  다시 가져가는 것도 이득처럼 보일 수 있어서).
- **결과(관찰)**: resnet은 acc_isolated 차이가 -0.10/+0.13/+0.15%p(평균 +0.06%p, 2/3만 양수) —
  기준 모델 자체의 seed 재현 편차(0.17%p)보다도 작아 잡음과 구분 안 된다. large-masked는
  +0.07/+0.54/+0.26%p(평균 +0.29%p, **3/3 양수**)로 부호는 일관되지만, 사전에 정한 +0.5%p 문턱을
  못 넘는다.
- **결정**: 둘 다 채택하지 않는다. large-masked는 3개 seed 모두 양수였지만 평균이 사전 문턱(+0.5%p)에
  못 미치고, 판정 기준은 결과를 본 뒤 낮추지 않는다. 이 차이가 잡음인지 실제 효과인지는 seed 3개로
  구분하지 못한다.
- **이유**: resnet은 파라미터를 3배 썼는데도 "전부 양수" 조건부터 못 미쳐서, "더 큰 모델이면
  된다"는 단순 가설과 안 맞는다. large-masked는 메커니즘상 기대(학습-추론 패딩 불일치 해소, 300
  프레임 고정 패딩과 같은 뿌리)가 있었지만, 이번 파일럿 규모(통화 3,000건)에서는 이득이
  문턱보다 작았다.
- **한계·주의**: resnet은 seed 2·3의 best_epoch이 33/35, 32/35로 35에폭 끝까지 오르고 있었을 수
  있어 더 학습시키면 달라질 여지가 있으나 확인하지 않았다. large-masked는 기존
  `SpeakerCNNLarge` 체크포인트에 평가 때만 풀링을 바꾼 것이 아니라 처음부터 마스크 풀링으로 새로
  학습한 것이다. 그래서 "학습 후 평가 방식만 바꾸기"(기존 large를 그대로 두고 평가 때만 마스크
  풀링)와 "학습 입력을 고정 길이로 채워 학습하기"는 시험하지 않았다. 원래 노렸던 짧은 발화(<0.5s, 0.5-1s) 구간에서는
  두 후보 다 이득이 없거나(부호가 갈리거나 오히려 나쁨) — "짧은 발화를 돕는다"는 가설은 이번에도
  지지되지 않았다.
- **후속 조치**: 모델 쪽 여유도 이번 조건에서는 소진된 것으로 본다. large-masked를
  전체 데이터(29,200통화)로 다시 볼 수는 있지만 우선순위는 낮다고 판단. 같은 날 기각된
  M2-AUG-001(SpecAugment/SWA)까지 합쳐, 이 입력·이 학습 방식에서 시도한 개선 후보(발화 길이 입력,
  시간·주파수 해상도 확대, L1 합치기, 데이터 보강, 모델 교체)가 전부 채택 근거를 못 얻었다 —
  남은 후보는 사전학습 SSL/AST뿐이거나, 제출 준비(새 PR, `.pt` 파일 포함) 쪽이 더 확실한 개선
  여지로 남아있다.
- **관련**: M2-CNN-008, M2-CNN-009, M2-CNN-002, M2-CNN-003, M2-CNN-007, M2-PAD-001, M2-VAL-004,
  M2-VAL-005(`docs/experiment_log.md`),
  [`m2_cnn_model_swap_seed_recheck.md`](../reports/mission2/m2_cnn_model_swap_seed_recheck.md).

## 2026-09-28 — [M2] 학습 때 데이터 보강(SpecAugment)과 가중치 평균(SWA) 기각 — 미리 정한 기준 미달

- **현황**: 지금 CNN 학습에는 데이터 보강이 전혀 없다. 학습 통화 정확도(92.6%)가 검증 통화(89.6%)보다
  높다는 점과, 데이터를 늘렸을 때 가장 크게 올랐다는 점에서 보강이 도움될지 시험했다(M2-AUG-001).
  약한 SpecAugment(주파수 띠 + 그 발화 길이의 10% 이하 시간 구간, 가려지는 면적 평균 약 20%)와 마지막
  5에폭 가중치 평균(SWA)을 통화 3,000건 파일럿에서 seed 3개로 시험했다. 공식 Validation은 쓰지 않았다.
- **결과**: SpecAugment는 기준(보강 없음)과의 차이가 −0.40 / +0.33 / −0.31%p(평균 −0.12%p)로 부호가
  갈렸고, SWA는 마지막 에폭 대비 평균 +0.18%p로 기준 +0.2%p에 근소하게 못 미쳤다(보강 없는 기준보다는
  평균 −0.22%p).
- **결정**: 이 두 가지를 채택하지 않는다. 판정 기준은 결과를 보기 전에 정했고, SWA의 +0.18%p도 기준을 옮기지
  않고 미달로 처리한다.
- **이유**: 차이가 같은 조건 반복 실행 편차(0.14~0.26%p) 안에 들어가고 부호가 일정하지 않다. SWA는 마지막

## 2026-09-28 — [M2] Decision Threshold는 0.5로 고정 — 과거 threshold 실험은 기록으로만 남김

- **현황**: 빅데이터센터 공식 안내(공지 메일 "제출파일 및 채점 기준 안내", 2026-09-24 관리자 공식
  공지 기준 — PR #31 리뷰에서 확인)에 따르면, 최종 결정 threshold는 Train/Validation 어느 데이터로
  찾았든 상관없이 **0.5로 고정**해야 하고(`예측값 ≥ 0.5 → 1`, 아니면 0), 다른 값으로 옮기면
  threshold 튜닝으로 본다. 답변은 Mission 3(다중 라벨) 예시가 중심이었지만 질문 자체는 미션을
  특정하지 않은 일반 원칙이라, 팀은 Mission 1·2에도 똑같이 적용한다.
- **과거 실험과의 관계**: M2-EXP-002(2026-09-15)와 M2-EXP-009(2026-09-18), 그리고 이를 기각한
  2026-09-15·2026-09-18 결정은 threshold를 0.5 밖으로 옮겨보고 "정확도가 안 올라서 기각"했다고만
  적혀 있다. 그때는 정확도만 보고 판단한 것이지만, **지금은 결과가 어땠든 threshold를 0.5 밖으로
  옮기는 것 자체가 허용되지 않는다.** 실험 사실은 그대로 남기되, 나중에 "정확도가 오르면 다시
  써볼 후보"로 읽으면 안 된다.
- **현재 우리 코드**: L1(`scripts/mission2_inference.py`)은 LightGBM `predict()`를 그대로 쓰고
  따로 threshold를 두지 않는다. L2(CNN) 경로(아직 main에 없음 — 2026-09-27 항목)는 두 클래스 점수
  중 큰 쪽을 고르는 방식(argmax)이라 0.5 기준과 같다. 둘 다 이 규정에 어긋나지 않는다.
- **후속 조치**: 제출 전 확인 목록(팀 규정 정리 문서)에 "threshold 0.5 고정" 항목이 이미 있다.
  Calibration(확률값 자체를 더 정확하게 만드는 것)은 허용되지만, 그 뒤에도 기준선은 0.5다.
- **관련**: M2-EXP-002, M2-EXP-009(`docs/experiment_log.md`).

## 2026-09-27 — [M2] 주파수 해상도(n_mels) 확대도 기각 — 짧은 발화를 돕는 시도 세 가지 모두 채택 근거를 못 얻음

- **현황**: M2-CNN-004/006(발화 길이 알려주기)과 M2-CNN-005(시간 해상도 확대)가 둘 다

  역전할지는 모른다.
- **가능한 설명(추정, 검증 안 함)**: 나쁜 영향이 짧은 발화에만 몰려 있어서, 단순한 학습 부족보다는

  가능성도 배제하지 못한다.
- **결정**: `n_mels=80`은 이 조건(3,000통화 pilot, 35에포크, seed 3개)에서 40보다 나은 근거를 못
  얻었고 오히려 나빠서 채택하지 않는다. 짧은 발화를 돕기 위한 세 시도(발화 길이 입력, 시간 해상도
  확대, 주파수 해상도 확대)가 모두 채택 근거를 못 얻었지만, 성격은 서로 다르다 — 발화 길이 입력은

  "판단 불가"로 접은 것이며, 이번 주파수 해상도 확대만 "나쁘다"가 확인됐다. 그래서 입력을 더
  세밀하게 만드는 방향은 당장 다시 시도하지 않는다. 추가 학습은 우선순위가 낮다고 보고 하지 않는다.
- **이유(추정)**: 짧은 발화는 원래 정보량 자체가 적은데(오디오 프레임 수가 애초에 적음), 그걸 더

- **후속 조치**: 짧은 발화 문제를 더 다루고 싶으면 "입력을 더 세밀하게" 방향 대신

## 2026-09-27 — [M2] 발화 길이를 모델에 알려주는 방식(SpeakerCNNLargeWithDuration) 채택 안 함 — 예전 +0.30%p 개선이 다시 해보니 재현되지 않음

  값들을 고정하지 않으면 우연이 신호처럼 보일 수 있다는 점이 M2-CNN-005(hop80 실험)를 다시

  데이터를 나누는 seed와는 다름)를 추가하고, M2-CNN-004를 이 값 1/2/3으로 3번 다시
  확인함(M2-CNN-006).
- **결과(관찰)**: 전체 정확도 차이(발화 길이를 알려주는 모델 − 기존 모델)는 -0.21/-0.22/-0.01%p로
  3번 다 마이너스, 평균 -0.15%p였다 — 예전(+0.30%p)과 반대 부호다. 실행 전에 미리 정한 판정

  -0.39%p~-0.95%p(평균 -0.70%p)로 나빠졌고 반복 편차보다 크다. 이 구간에는 발화 길이 입력이

  <0.5초 구간은 좋아졌다 나빠졌다 해서 판단 불가.
- **결정**: 이 방식(SpeakerCNNLargeWithDuration)은 쓰지 않는다. M2-CNN-004의 +0.30%p는 개선
  근거로 쓰지 않는다(다시 해보니 재현되지 않았으므로). M2-CNN-005(hop80)는 별개다 — hop80은
  seed를 고정해서 다시 확인한 적이 없고, 원래 "결과가 흔들려서 판단할 수 없다"는 이유로 접은
  것이라, 이번 결과가 hop80 효과의 유무를 알려주지는 않는다. 두 실험이 공통으로 주는 교훈은

- **이유**: 지난 세션에서 "대회 채점이 정확도 하나만 보니까, 격차가 벌어져도 정확도만 보고
  다시 판단하자"고 했던 논리 자체는 맞았지만, 실제로 다시 재봤더니 그 정확도 개선이
  재현되지 않았다(처음 결과는 우연이었을 가능성이 크다). "다시 판단해볼 이유가 있다"는 것과

- **후속 조치**: `--torch-seed`는 앞으로 이런 비교를 할 때 기본으로 쓴다(한 번만 실행한 결과를

  채택 근거를 못 얻었다(위 항목).

## 2026-09-23 — [M2] L1·L2를 발화 단위로 비교 — L2가 더 나은 구간(겹침·짧은 발화) 확인, L2 쓰기로 한 결정 유지 (이유는 미검증)

## 2026-09-15 — [M2] 분류할 때 볼 수 있는 건 그 발화 하나뿐 — 같은 통화의 다른 발화 정보는 전부 금지

## 2026-09-15 — [M2] class_weight·threshold·겹침 데이터 처리 실험 전부 기각

- **결정**: 정답 기준선(threshold) 보정, `class_weight="balanced"`, 겹치는 학습 데이터
  빼기·비중 줄이기를 전부 기각.

  쓸 수 없게 됐다 — 위 2026-09-28 항목 참조. class weight·겹침 데이터 처리의 기각은 그대로
  정확도 기준의 판단이다.

## 2026-09-10 — [M2] 라벨 확인용으로 사람이 대화 내용(text)을 읽음 — 팀 내부 판단, 운영진 확인 전

- **공식 규정과의 관계**: 공식 문제는 Mission 2에서 `text`를 모델 입력(피처)으로 쓰는 것을
  금지한다. 하지만 사람이 라벨을 점검하려고 읽는 것까지 허용하거나 금지한다고 적은 문구는 우리가

  설명하지 않는다.
- **후속 조치 (아직 안 함)**: (1) 운영진에 문의해서 이 사용이 괜찮은지 확인하거나, (2) 텍스트 없이

## 2026-09-10 — [M1] GBM과 LR 비교, LR을 1차 후보로 정함

## 2026-09-10 — [M1] baseline 단계에서는 k-fold 교차검증 생략

- **결정**: baseline 단계에서는 따로 k-fold 교차검증을 하지 않는다.
- **이유**: 규모가 큰 고정 Validation 데이터와 내부 확인 결과가 비슷했고, baseline 단계라
  시간·계산 비용을 고려해 우선 생략함. 부트스트랩 신뢰구간과 다른 통계 방식의 신뢰구간이 서로
  맞는다는 건 불확실성 계산 방법이 맞다는 교차 확인일 뿐이지, 데이터를 어떻게 나누든 모델이
  안정적이라는 증거로 쓰지는 않는다.
- **한계/후속**: 지금 결과는 데이터를 나누는 방식에 따라 얼마나 흔들리는지는 확인 안 한 상태다.
  최종 모델을 정하기 전에 필요하면 반복 holdout, k-fold, 또는 쌍(paired) 비교를 한다.

## 2026-09-10 — [M1] "통계적으로 동급"이라는 표현 수정 (외부 리뷰 반영)

- **결정**: PR 설명과 verdict에 있던 "두 모델 신뢰구간이 겹쳐서 통계적으로 동급"이라는 표현을
  "차이가 작음(0.19%p)"으로, "과적합·데이터 누수 징후 없음"을 "뚜렷한 징후는 관찰되지 않음"으로
  고침.
- **이유**: GBM과 LR은 같은 3,640개 샘플을 놓고 비교한 것(paired comparison)이라, 각 모델의
  신뢰구간이 겹친다는 것만으로는 통계적으로 같다고 말할 수 없음. 제대로 비교하려면 McNemar
  검정이나 paired bootstrap 같은 방법이 필요함.
