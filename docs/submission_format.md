## 실행 명령과 CSV 컬럼 (p.11 「실행규칙」)

> 참가자는 학습 완료된 모델과 추론 코드를 함께 제출한다.
> 평가 시에는 주최 측이 제공하는 Validation 또는 Test 입력 폴더를 대상으로
> ● python inference.py --audio_dir {wav folder} --label_dir {json folder} --ckpt_path
> {checkpoint file} --output ./outputs/mission{미션번호}.csv
>
> 명령어를 1회 실행하여 결과 파일을 생성할 수 있어야 한다.
> 참가자가 내부적으로 전처리, feature 추출, 모델 추론, 후처리 등 여러 단계를 사용하더라도,
> 최종 실행은 mission별 위 명령어 한 번으로 완료되어야 한다.
> 출력 파일은 각 Mission별 지정된 CSV 형식에 맞춰 저장해야 한다.
>
> ● Mission 1 csv: [audio file name], [gender]
> ● Mission 2 csv: [audio file name], [startAt], [endAt], [speaker]
> ● Mission 3 csv: [label file name], [symptom]

- 옵션 앞의 하이픈은 텍스트 레이어에서 ASCII `-` 두 개(U+002D)입니다. 렌더에서는 긴 대시처럼 보입니다.
- 대괄호는 컬럼 이름을 표시하는 기호로 봅니다. 그래서 헤더는 `audio file name,gender` 형태로 씁니다. `registry.MISSION_COLUMNS`가 이 형태입니다.

## Mission 1 (p.7)

> 입력: 음성 (원천데이터)
> ●라벨링데이터는 학습시 startAt, endAt, Speaker만 사용 가능,
> inference시 startAt, endAt, Speaker만 사용 가능
>
> 출력: 남/여 분류 (라벨링데이터의 gender)
>
> 성능 평가에는 Accuracy를 사용함

- `gender` 셀에 어떤 값을 쓸지는 원문에 없습니다. "라벨링데이터의 gender"라고만 되어 있으니, 라벨 JSON의 gender 값을 그대로 씁니다.

## Mission 2 (p.8)

> 입력: 한 사람의 한 발화 조각
> ● 조각의 기준은 라벨링데이터의 startAt, endAt으로 정함.
> ● startAt, endAt 이외의 annotation은 사용불가 - text 또한 사용불가
> ● 발화의 홀짝 등 순서 사용불가
>
> 출력: 신고자(speaker=1) / 119대원(speaker=0) 분류
> 성능 평가에는 Accuracy를 사용함.

- `speaker` 값은 원문에서 `speaker=1` / `speaker=0`로만 표기돼 있습니다. 정수 0/1로 쓰는 근거입니다.
- `startAt`/`endAt`의 단위와 소수점 형식은 원문에 없습니다. 라벨 JSON의 값을 그대로 옮깁니다.

## Mission 3 (p.9)

> 출력: 환자의 증상 (라벨링데이터의 symptom)
> ※ 개수는 0개~9개 일 수 있음.
>
> \* symptom 클래스는 다음의 9개만 취급
> 고열, 구토, 두통, 복통, 어지러움, 열상, 오심, 전신쇠약, 호흡곤란
> \* 데이터의 symptom list에 위 9개 이외의 symptom이 포함되어 있는 경우,
> 해당 symptom은 평가 대상에서 제외하며, 전처리 과정에서 symptom list에서 제거
> (단, 샘플 전체를 제거하는 것이 아니라, target symptom 9개에 해당하지 않는 label만 제외)
>
> \* symptom 클래스는 string type으로 처리함.
>
> \* e.g.,
> Sample(X) 1의 symptom(Y) => [‘두통’, ‘복통’, ‘찰과상’]
> 위 경우, sample 1에 대한 예측된 symptom은 9개 클래스에 포함되는 [‘두통’, ‘복통’] 을 string type으로 출력해야 함.

- 예시의 따옴표는 **작은따옴표**입니다. 텍스트 레이어의 코드포인트는 U+2018 `‘`와 U+2019 `’`(둥근 작은따옴표)입니다. 큰따옴표가 아닙니다.
- 구분자는 쉼표(U+002C) 뒤 공백 하나이고, 대괄호는 ASCII `[` `]`입니다.
- 둥근 따옴표는 InDesign이 따옴표를 자동으로 바꾼 결과로 보입니다. 그래서 의도한 값은 Python `str(list)`의 `['두통', '복통']`(ASCII `'`, U+0027)로 해석합니다. 사령탑이 2026-10-06에 이 해석으로 확정했습니다(아래 표). 10-10 멘토링 때 주최 측에 한 번 더 확인합니다.
- 라벨 순서는 원문에 규정이 없습니다. 예시의 순서(두통, 복통)는 위 9개 클래스 목록의 순서와 같습니다.
- 증상이 0개일 때 어떻게 쓸지는 원문에 없습니다("개수는 0개~9개 일 수 있음"만 있음). p.10의 F1 계산 예시 표에는 "(없음)"이 나오지만, 이것은 설명용 표입니다.

## 원문에 없는 항목

아래 항목은 출제문제 PDF(13쪽 전체)와 `0820_DCC 참가자 매뉴얼.pdf` 어디에도 규정이 없습니다. 팀 기본값으로 정하고, 바꿀 때는 이 표를 고칩니다.

| 항목 | 원문 | 팀 기본값 |
|---|---|---|
| CSV 인코딩 / BOM | 없음 | UTF-8, BOM 없음 (`registry.CSV_ENCODING`) |
| 행 순서 | 없음 | 입력 파일 이름 정렬 순서 |
| 행 순서 (M2) | 없음 | 파일 이름 정렬, 같은 파일 안에서는 라벨 JSON의 `utterances` 순서 (#51). 이 순서는 출력 행 순서에만 쓰고 예측에는 쓰지 않음 (p.8 "발화의 홀짝 등 순서 사용불가") |
| M1 `gender` 값 | "남/여 분류 (라벨링데이터의 gender)" | 라벨 JSON의 gender 값 그대로 |
| M2 `startAt`/`endAt` 단위·소수점 | 없음 | 라벨 JSON의 값 그대로 |
| M2 `speaker` 타입 | `speaker=1` / `speaker=0` | 정수 0/1 |
| M3 증상 0개 | 없음 | `[]` (사령탑 확정 10-06). 9개 확률이 모두 0.5 미만이면 후처리 없이 `[]`로 제출. argmax 1개를 채우는 min-1 규칙은 **주최 측 답변으로 금지** (10-09) |
| M3 symptom 셀 | `‘ ’` (U+2018/2019) | Python `str(list)` 형식 `['두통', '복통']` (ASCII `'`, 쉼표 뒤 공백 한 칸), 라벨 순서는 `TARGET_SYMPTOMS` 순서 (사령탑 확정 10-06). CSV에서는 표준 QUOTE_MINIMAL에 따라 `"['두통', '복통']"`처럼 큰따옴표로 감싸짐. 테스트는 `pd.read_csv` 후 `ast.literal_eval`로 원래 리스트가 나오는지 왕복 검사. 10-10 멘토링에서 주최 측 확인 예정 |
