## 3. 성능 개선 전략 (Phase 1, 10/6~10/11)

원칙: **Mission당 효과가 가장 클 것으로 보는 실험 1개**에 집중한다. 이미 기각된 미세 조정(threshold·class_weight·겹침 가중 등)은 다시 하지 않는다.

### 3.1 M1·M2 공통 — 사전학습 음성 임베딩 (핵심 실험)

현재 두 Mission 모두 손으로 설계한 50여 차원 통계에서 막혀 있다. 주최 측 힌트(Wav2Vec2/HuBERT/AST)도 사전학습 음성 모델을 가리킨다.

- **방식**: 공개 사전학습 음성 모델을 **고정(frozen)**한 채 중간 레이어 hidden state를 mean+std pooling해 임베딩을 만들고, 그 위에 LR/LGBM 헤드를 학습한다. fine-tuning보다 싸고 안정적이며 T4로도 충분하다.
- **후보 모델** (하나만 먼저 시도한다):
  1. `microsoft/wavlm-base-plus` (화자·채널 특성 표현이 강함, 95M) ← **1순위**
  2. `facebook/wav2vec2-xls-r-300m` 또는 한국어 wav2vec2 (대안)
  3. (M1 한정) SpeechBrain ECAPA 화자 임베딩
- **추출기 하나, 헤드 둘**: 임베딩 추출 코드를 공유하고 M1(신고자 구간 연결 → 통화 단위 임베딩)과 M2(발화 조각 단위 임베딩)는 헤드만 따로 둔다. 5명 중 3명이 음성을 맡고 있으니 작업을 나눈다.
- **연산 계획**: M2 Training 발화는 89만 개다. 우선 **통화 단위로 10만~20만 발화를 표본 추출**하고(통화 그룹 유지), 16kHz·최대 6초로 crop한다. Val 11.2만 발화는 T4에서 수십 분 수준이다. 레이어는 Training 내부 holdout으로 2~3개(예: 4/8/12층)만 비교한다.
- **기대치** (경험적 추정이며 실험으로 확인해야 한다): M2 +4~8%p, M1 +1~3%p.
- **추론 시간 리스크**: 평가 환경의 시간 제한을 모른다. 배치 추론과 GPU/CPU 자동 선택을 넣고, CPU에서 Val 전체가 몇 시간 걸리는지 측정해 둔다.

**M2 통화 내 다른 발화 정보 사용 금지 (주최 측 공식 답변으로 확정)**: 주최 측 답변은 "분류 대상 발화 조각(startAt~endAt)의 정보만 사용"하고 "각 발화는 독립적으로 입력된다고 가정"하라는 것이다. 같은 통화의 다른 발화로 계산한 길이·평균·상대값 등은 순서를 쓰지 않더라도 금지된다. 임베딩 파이프라인도 다음을 지킨다.
- 통화 단위 정규화 금지: 전체 WAV 기준 음량·peak 정규화, 통화별 CMVN(평균·분산 정규화), 통화별 z-score 등
- 통화 내 클러스터링, 화자 분리(diarization), 같은 통화 발화 간 유사도 사용 금지
- 짧은 구간을 늘릴 때는 zero-pad만 쓴다. 앞뒤 발화 음성을 이어 붙여 길이를 늘리지 않는다.
- 추론 시 모델은 `eval()` 상태로 둔다. 배치 구성이 예측에 영향을 주면 안 된다(BatchNorm 학습 모드 금지).
- 정규화 통계를 쓸 때는 Training 전체에서 미리 계산한 고정값만 사용한다.

현 L1 파이프라인(`src/dcc_data/mission2_features.py`)은 발화 구간을 잘라 그 구간만으로 특징을 계산하므로 이 기준에 맞는다(2026-10-05 확인).
※ M1은 규정상 `Speaker`를 써서 신고자 구간을 모으는 것이 허용되므로 M2 기준과 혼동하지 않는다.

### 3.2 M3 — "데이터를 다 쓰고, 임계값을 제대로" (핵심 실험)

| 레버 | 근거 | 우선순위 |
|---|---|---|
| **Training 100% 사용** | 지금까지 20~40%만 학습했다. 데이터 양 자체가 가장 큰 레버다 | ★★★ |
| **최소 1개 레이블 보장 후처리** | EDA상 목표 증상이 0개인 통화는 Training·Val 모두 **0건**이다. 임계값을 넘는 증상이 없으면 확률이 가장 높은 증상 1개를 출력한다. 라벨과 무관한 일괄 규칙이라 규정상 문제없다 | ★★★ (거의 공짜) |
| **증상별 임계값** | Macro F1은 증상별 임계값에 민감하다. 과거 기각 이유는 재현 불가(배열 유실)였고 기법 자체의 문제는 아니었다. **Training 내부 holdout으로만 선택**하고 배열을 ckpt 메타에 저장하면 재현성과 Val 오염을 모두 해결한다 | ★★☆ |
| **더 강한 인코더** | `klue/roberta-base`(또는 시간이 되면 `klue/roberta-large`)를 KcBERT와 같은 조건으로 대조한다. 대화 전사는 KcBERT의 학습 도메인(댓글)과 다르다 | ★★☆ |
| **TF-IDF 문자 n-gram LR 앙상블** | 멘토 답변대로 서로 보완될 때만 쓴다. 확률 평균 가중치는 Val로 정할 수 있다(Q&A 허용) | ★☆☆ |

권장 실행 순서: ① 현 청크 KcBERT를 Training 100%(내부 10% holdout은 early stopping·임계값 선택용)로 학습한다 → ② 후처리 2종(1개 보장 + 증상별 임계값)의 효과를 Val로 확인한다 → ③ 남는 GPU 시간에 roberta를 대조한다.
※ 2026-09-30 결정(80:20, th=0.5)은 **실험 간 비교 기준**으로 유지한다. 최종 모델은 비교가 끝난 설정으로 **Training 전체를 학습**한다(최종 재학습은 이 비교 기준과 별개의 단계로 명시).

## 6. 하지 않을 것 (Stop-doing)

- 이미 기각된 미세 조정 재시도(M2 threshold/class_weight/겹침 가중, M1 GBM↔LR 재비교)
- Mel+CNN 직접 학습 같은 새 아키텍처 탐색(시간 대비 기대 이득이 임베딩 방식보다 낮음)
- M2에서 같은 통화의 다른 발화 정보 사용(통화 내 비교·정규화·클러스터링): **주최 측 답변으로 금지 확정**
- 공식 답변 없이 회색지대 기법 사용(ASR 텍스트를 M2에 사용 등)
- Validation을 학습 배치에 넣는 모든 형태
- 10/12 동결 이후의 기능 추가
