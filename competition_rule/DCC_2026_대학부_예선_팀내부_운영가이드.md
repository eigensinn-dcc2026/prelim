## 5. 데이터 다운로드와 보관

### 5.1 다운로드 절차

1. 공식 Google Drive에서 대학부 배포본을 다운로드한다.
2. 압축파일이 있다면 원본을 보존한 상태에서 별도 폴더에 해제한다.
3. 파일 수, 전체 크기, 폴더 구조를 기록한다.
4. `Training`과 `Validation`을 물리적으로 분리한다.
5. Validation 데이터가 학습 코드에 들어가지 않는지 확인한다.
6. 전체 팀원이 각자 중복 다운로드하기보다 원본 보관 담당자와 공유 방식을 정한다.

### 5.2 권장 폴더 구조

```text
data/
├─ raw_original/          # 주최 측 배포 원본, 수정 금지
├─ train_seoul/           # 학습에 허용된 서울 데이터
├─ validation/            # 학습 사용 금지
├─ processed/
│  ├─ mission1/
│  ├─ mission2/
│  └─ mission3/
└─ manifests/             # 파일 목록·크기·해시·분할 기록
```

### 5.3 데이터 규칙

- 주최 측 Google Drive로 배포된 대회 데이터만 사용한다.
- 다른 AI-Hub 데이터셋과 동일 데이터셋의 별도 추가본을 포함하여, Google Drive 배포본 외 데이터는 사용하지 않는다.
- Training set으로는 서울 데이터만 사용한다.
- Validation 데이터를 Training set에 직접 편입하거나 Backpropagation에 사용하면 **실격 처리**된다.
- Mission마다 지정된 입력과 annotation만 사용한다.
- 정답 label에 따라 샘플별 전처리를 다르게 적용하지 않는다.
- 평가 데이터에만 유리한 특별 전처리를 적용하지 않는다.

### 5.4 사전학습 모델과 Validation 운영 기준

2026-08-22 관리자 공식 Q&A를 다음과 같이 적용한다.

| 항목 | 팀에서 허용 | 팀에서 금지 |
|---|---|---|
| 공개 Pre-trained 모델 | Hugging Face 등에서 직접 다운로드하여 로컬 Inference 또는 Fine-tuning | 외부 데이터셋을 별도로 추가하여 학습 |
| 상용 AI | 코드 작성·검토 등 개발 보조는 별도 공식 확인이 필요한 경계 사례 | GPT·Claude 등 외부 상용 AI API를 평가·추론 파이프라인에서 직접 호출 |
| Validation | 모델 구조·하이퍼파라미터 선정, 최종 모델 선택, 앙상블 가중치 조정 | Training set 편입, 학습 배치 투입, Backpropagation |
| 학습 제어 | Early Stopping, Best Checkpoint 선정, Learning Rate Scheduler 트리거 | Validation sample을 이용한 가중치 업데이트 |

운영 원칙:

1. DataLoader 단계에서 `train`과 `validation` 경로를 명확히 분리한다.
2. Validation loop는 `model.eval()`과 gradient 비활성화 상태로 실행한다.
3. Early Stopping, checkpoint 선택, 하이퍼파라미터 변경 근거를 실험 로그에 남긴다.
4. 앙상블 가중치를 Validation으로 정했다면 후보와 선택 결과를 기록한다.
5. 공지에서 명시하지 않은 전처리 통계는 Training 데이터만으로 계산한다.

## 6. 멘토링 게시판 운영

### 6.1 공식 규칙

- 게시판은 기존 캠프 페이지가 아닌 별도 페이지에서 운영된다.
- 게시글은 사전에 발급된 팀 공용 계정으로만 작성한다.
- 질문은 팀당 하루 1회만 가능하다.
- 오후 5시까지 등록하면 당일 자정까지 답변하는 것이 원칙이다.
- 멘토 사정에 따라 답변이 익일로 넘어갈 수 있다.
- 게시글을 올리기 전에 팀 내부에서 질문을 충분히 논의한다.

### 6.2 팀 질문 작성 절차

1. 팀원이 질문 후보를 공유한다.
2. 이미 공식 문서에 답이 있는지 확인한다.
3. 재현 가능한 최소 예시와 현재 시도 내용을 정리한다.
4. 데이터·규칙·모델·실행 중 질문 유형을 분류한다.
5. 하루 1회 제한을 고려해 우선순위가 가장 높은 질문을 선택한다.
6. 답변을 받은 뒤 질문과 답변을 팀 지식 문서에 요약한다.

### 6.3 권장 질문 형식

```text
[질문 유형] 규칙 / 데이터 / 실행 / 평가 / 모델

1. 확인하려는 사항
2. 공식 문서에서 확인한 관련 문구
3. 현재 팀의 해석
4. 실제로 막힌 사례 또는 최소 재현 예시
5. 주최 측에 확인받고 싶은 단일 질문
```
