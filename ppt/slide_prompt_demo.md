# 새 슬라이드 요청서: "한 통화가 처리되는 과정 (합성 예시)"

대상: `ppt/build_deck.js`(pptxgenjs). 작업자는 Claude 또는 Codex. `.pptx`는 직접 열어 고치지 말고 `node build_deck.js`로만 재생성한다.

## 1. 삽입 위치

- **기존 18장(성능 요약과 교훈)과 19장(사회안전 시사점과 향후 계획) 사이**에 새 슬라이드를 넣는다. 새 슬라이드가 19장이 되고, 기존 19장은 20장, 마무리는 21장이 된다.
- 이유: 흐름이 "성과(숫자) → 실제로 어떻게 쓰이는가(데모) → 사회안전 시사점·향후 계획"이 된다.
- 04 섹션 라벨과 소제목: `04 종합 및 시사점` / `(2) 한 통화가 처리되는 과정 (합성 예시)`. 기존 소제목은 `(2) 사회안전 시사점과 향후 계획` → `(3) …`로 바꾼다.
- 따라 바꿀 것
  - 헤더의 페이지 번호(`header(..., page)`): 기존 19 → 20. 마무리 장은 번호를 쓰지 않는다.
  - 3장 목차 04 섹션 항목에 "한 통화 처리 시나리오"를 추가한다 (1. 성능 요약과 교훈 / 2. 한 통화 처리 시나리오 / 3. 사회안전 시사점과 향후 계획).
  - 기존 19장(→20장) 상단의 `flow_pipeline.gif` 줄은 새 슬라이드와 중복되므로 **삭제**하고, 아래 카드 두 개를 위로 당겨 여백을 정리한다.
  - 발표자 노트(`addNotes`)에서 장 번호를 언급한 부분이 있으면 갱신한다.

## 2. 슬라이드 구성 (공식 헤더 띠 + 기존 `header`, `coreMsg`, `caption` 함수 사용)

- 핵심 메시지(한 줄, 40자 이내): `신고 전화 한 통이 들어오면 세 모델이 순서대로 결과를 정리한다.`
- 본문: 영상(GIF) 하나를 가운데에 크게 (가로 12.33in, 높이 약 4.4in, 비율 약 2.8:1).
- 영상 아래 한 줄: `※ 합성 예시 — 실제 통화·전사문이 아니며, 모든 출력은 요원의 판단을 돕는 정보로 사람이 최종 확인한다.`
- 글은 이 세 줄이 전부다. 다른 설명 문장은 넣지 않는다.

## 3. 영상 요구사항 (`ppt/tools/make_gif_scenario.py` → `ppt/figures/anim/call_scenario.gif`)

도구는 PIL 또는 matplotlib. 생성형 영상 도구는 쓰지 않는다 (순서·내용 정확성이 필요하기 때문).

**규격**: 1920×690 (비율 2.78:1), 약 12초, 무한 반복, 용량 1.5MB 이하, 전역 팔레트를 사용해 곡선이 깨지지 않게 한다. 한글은 맑은 고딕. 팔레트는 네이비 `#2F4E91`, 스카이 `#009DDA`, 민트 `#8BC34A`, 빨강 `#E53935`(강조 최소), 연한 파랑 `#EAF3FA`, 회색 `#E0E0E0`. 아이콘은 `ppt/figures/icons/`의 `flow_*.png`, `sym` 계열은 `ppt/figures/canva/sym_0~8.png`를 재사용한다.

**첫 프레임 = 마지막 완성 화면** (PDF·썸네일에서도 뜻이 통하게). 끝에서 처음으로는 크로스페이드로 잇는다.

**화면 배치**
- 왼쪽 40%: "통화" 패널. 위에 파형 타임라인(발화 4개: 대원·신고자·대원·신고자), 아래에 합성 전사문 2~3줄.
- 가운데 20%: 단계 배지 3개를 세로로 (Mission 2 → Mission 1 → Mission 3). 각 배지에 짧은 라벨(`발화별 화자 분류`, `신고자 성별`, `증상 태깅`).
- 오른쪽 40%: "상황실 화면" 카드. 성별 배지, 증상 태그, 하단 유의 문구 아이콘.

**스토리보드 (총 12초 + 완성 화면 유지 2초)**
1. 0~2초: 파형이 왼쪽에서 흐르며 발화 블록 4개가 나타난다. 전사문은 아직 흐릿하다.
2. 2~5초: **Mission 2.** 블록을 **하나씩 따로** 강조(나머지는 회색으로 가림)하며 대원(네이비)/신고자(스카이)로 칠한다. 각 블록이 자기 자신만으로 판정된다는 점이 보이게 한다. 다른 블록과 연결선을 그리지 않는다.
3. 5~7.5초: **Mission 1.** 신고자(스카이) 블록만 가운데로 모이고 `여성` 배지가 켜진다. 대원 블록은 쓰이지 않는다.
4. 7.5~10초: **Mission 3.** 전사문(텍스트)에서 증상 키워드가 강조되고 해당 증상 아이콘이 켜진다. 음성은 쓰지 않는다.
5. 10~12초: 상황실 카드가 채워진다 (성별 배지, 증상 태그, 유의 문구).

**합성 예시 문구** (실제 데이터 아님): 대원 "119입니다. 어디가 불편하세요?" / 신고자 "머리가 너무 아프고 어지러워요." 증상 태그는 `두통`, `어지러움`.

## 4. 지켜야 할 규칙 (어기면 불합격)

- **M2는 발화 하나씩 독립 판정**: 다른 발화·발화 순서·전사문·통화 단위 정보를 쓰는 것처럼 그리지 않는다.
- **M1은 신고자 구간만**, **M3는 전사문 텍스트만** 쓴다고 그려야 한다.
- 영상과 슬라이드에 새 성능 수치나 확률을 넣지 않는다 (예시 화면에도 점수 표기 금지).
- 실제 통화·전사문·인물 얼굴을 쓰지 않는다. 합성 예시라는 표기를 영상 안 또는 캡션에 둔다.
- 다른 팀의 자료를 참고했다는 표현을 쓰지 않는다.
- 외부 서비스나 다운로드는 쓰지 않는다. 새 패키지를 설치하지 않는다.

## 5. 검증 (완료 조건)

1. `node build_deck.js`로 `.pptx`를 재생성한다 (PowerPoint로 열려 있으면 먼저 닫는다).
2. 새 19장과 기존 19장(→20장)을 PNG로 렌더링해 글자 넘침·겹침이 없는지 본다. 영상의 첫 프레임이 완성 화면인지 확인한다.
3. 페이지 번호, 목차, 소제목 번호가 모두 맞는지 확인한다.
4. GIF 용량이 1.5MB 이하이고, pptx 전체가 11MB 이하인지 확인한다.
5. 커밋은 하지 않고 변경 파일 목록과 확인 결과만 보고한다.
