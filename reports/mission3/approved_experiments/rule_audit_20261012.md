# M3 실험 규정 점검 — 2026-10-12

## 결론

네 실험 모두를 무조건 적합하다고 확정할 수는 없다. 손실 집계 변경과 Training 내부 OOF 증류는 확인한 규정에 부합한다. 선택적 512토큰 재검토는 허용으로 해석되지만 구조 자체에 대한 공식 답변은 확인하지 못했다. 새 수동 근거·상태 주석을 학습 정답으로 사용하는 실험은 주최 측의 명시적 확인 전까지 보류한다.

현재 실제 대회 데이터의 GPU 학습은 시작하지 않았고, 사람 검토 완료 주석도 없다. 주석 양식 생성과 코드 검증만으로 금지된 보조 정답 학습이 이루어진 것은 아니다. 이 점검은 주최 측의 사전 승인이나 최신 공지를 모두 확인했다는 보증이 아니다.

## 근거와 확인 범위

1. 공식 원문: 0820 출제문제 PDF(`공식전달사항/0820_DCC 대학부_예선_출제문제.pdf`, 저장소 밖 보관본). 5쪽 공통 조건, 9쪽 M3 입력·출력, 11쪽 실행 규칙을 직접 추출해 대조했다.
   - 배포 데이터만 사용하고 외부 데이터를 추가하지 않는다.
   - 각 미션에 지정된 입력·출력만 사용한다. M3 입력은 전사 텍스트, 출력은 지정된 9개 증상이다.
   - 공개 사전학습 모델은 허용하고 상용 AI API는 금지한다.
   - Training은 서울 데이터만 사용하고 공식 Validation은 학습에 사용하지 않는다.
   - 실제 라벨에 따라 달라지는 샘플 전처리와 평가 데이터에서만 유리한 특별 전처리를 금지한다.
2. 저장된 [공식대조본](<../../../competition_rule/DCC_2026_대학부_예선_문제명세_공식대조본.md#L103>)의 주최 측 Q&A 전사: 최종 decision threshold는 모든 클래스에서 0.5로 고정하며, 손실 설계·calibration 및 학습·앙상블·분석 목적의 OOF는 허용한다고 기록되어 있다. 이 임계값 Q&A의 게시 일시는 저장본에 없으며, 이번 점검에서 게시판 원문을 재확인하지 못했다. 원 PDF 자체에는 이 후속 Q&A가 포함되어 있지 않다.
3. 공개 웹 검색은 세부 쟁점을 해소할 공식 답변을 제공하지 못했다. 기존 멘토링 게시판 탭도 브라우저 연결 시간 초과로 읽지 못했다. 따라서 추가 수동 주석과 동적 라우팅의 명시적 허용 답변은 미확인 상태다. 팀 내부 해석을 공식 허가로 취급하지 않았다.

## 실험별 판정

| 실험 | 판정 | 근거·조건 |
|---|---|---|
| soft-F1을 실제 유효 배치 전체에서 집계 | 적합 | 동일 Training 전사·9개 증상으로 손실 계산 범위만 변경한다. 입력·정답 종류를 늘리지 않고 최종 판정은 0.5다. |
| Training 내부 OOF 교사 → KcELECTRA 증류 | 적합 | 배포 Training의 기존 전사에 대한 자체 모델 확률을 보조 목표로 사용한다. 외부 문장·데이터를 생성하거나 상용 API를 호출하지 않는다. 저장 Q&A의 학습 목적 OOF 허용과 부합한다. |
| 사람의 근거 구간·긍정/부정/미확인 상태 보조 감독 | 보류: 명시적 확인 필요 | 추론 입력은 전사만이어도 학습 출력에 새 span/state 정답이 추가된다. '지정된 입력·출력만 사용' 및 '전사 외 라벨링 데이터 사용 불가'의 적용 범위가 불명확하다. 내부 학습용 추가 주석이라는 이유만으로 허용이라고 단정할 수 없다. |
| 불확실한 긴 통화만 512토큰 재검토 | 조건부 적합으로 해석 | 라우팅은 전사 길이와 모델 확률만 사용하며 실제 symptom 정답을 읽지 않는다. 최종 확률을 라벨로 바꾸는 기준은 항상 0.5다. 동일하게 고정된 라우팅을 모든 평가 입력에 적용해야 한다. 공식 문구가 예측값에 따른 동적 처리까지 금지하는지는 직접 확인되지 않았다. |

### OOF 증류의 구현 조건

- 23,408건 fitting split 내부에서 새 3-fold 교사를 만들고 5,792건 내부 holdout은 교사·학생 역전파에서 제외한다. 내부 holdout은 공식 Validation과 다르다.
- 교사는 매 fold 공개 사전학습 가중치에서 시작한다. 전체 fitting 데이터로 이미 학습된 task checkpoint를 inner 교사의 초기값으로 쓰지 않는다.
- 신경망과 TF-IDF/LR 모두 해당 inner fitting fold로만 학습한다. 학생의 각 soft target은 그 행을 학습하지 않은 교사에서 나온다.
- 파일명·통화 ID·전사 해시를 분할 검증용으로 사용하며 모델 입력으로 넣지 않는다.
- 공개 pretrained 모델 다운로드는 외부 학습 데이터 추가나 상용 추론 API 호출과 구별된다. 최종 추론은 로컬 가중치와 tokenizer로 실행한다.

구현 근거: [교사 학습](<../../../scripts/train_mission3_approved.py#L262>), [OOF 누수 검사](<../../../src/dcc_data/mission3_approved_core.py#L66>).

### 추가 사람 주석의 실행 제한

기존 코드에는 검토 완료 JSONL 및 `--human-annotation-rules-confirmed` 없이는 사람 감독 실험을 실행하지 못하도록 제한이 있다. 그러나 이 플래그는 실행자의 확인 표시일 뿐 주최 측 허가를 입증하지 않는다. 명시적 공식 답변 없이 플래그를 켜지 않는다. 동일 attention/residual 구조를 기존 9개 symptom 정답만으로 학습하는 대조군은 추가 주석 문제와 별개다.

### 라우팅 margin과 판정 threshold의 구분

`min(abs(p-0.5)) <= margin`은 어느 모델의 확률을 사용할지 선택하는 기준이다. 선택된 모델의 확률을 `>=0.5`로 이진화한다. margin을 내부 검증 F1로 선택하는 것은 모델 선택으로 해석되며, 클래스별 판정 경계를 0.37 등으로 옮기는 threshold tuning과 같지는 않다. 다만 실제 정답을 이용한 라우팅, 평가 폴더별 다른 정책, 평가 결과를 본 뒤 개별 샘플을 수동 교정하는 방식은 허용되지 않는다. 제출 전 하나의 margin/정책을 고정해야 한다.

구현 근거: [라우팅](<../../../src/dcc_data/mission3_approved_core.py#L159>), [추론 입력 경계와 재검토](<../../../scripts/inference_mission3_approved.py#L56>).

## 실험 허용 여부와 별개인 제출 형식 문제

현재 `inference_mission3_approved.py`는 실험용 harness이며 정식 제출 패키지가 아니다. `--ckpt-path`, `--label-dir` 등 실험 인자를 쓰고 cascade에는 별도 long checkpoint가 필요하다. 공식 PDF 11쪽의 아래 실행 계약과 아직 일치하지 않는다.

```text
python inference.py --audio_dir {wav folder} --label_dir {json folder} --ckpt_path {checkpoint file} --output ./outputs/mission3.csv
```

채택 후보가 생기면 표준 `inference.py`에 통합하고, 단일 `--ckpt_path`로 필요한 가중치·tokenizer·고정 라우팅 정책을 모두 복원하도록 패키징해야 한다. 인터넷 없는 환경에서 한 명령으로 모든 JSON 행과 9개 증상 CSV를 생성하는지 확인해야 한다. 여러 모델/단계를 내부적으로 쓰는 것 자체는 PDF에서 허용한다. 현재 harness를 그대로 제출하면 실행 규격 문제가 생긴다.

## 공식 문의 초안 — 전송하지 않음

1. M3의 배포 Training 전사만 사람이 읽고 증상별 근거 문자 구간 및 긍정/부정/미확인 상태를 추가 주석하여 학습 시 보조 손실로 사용하는 것이 허용되나요? 추론은 전사만 입력하고 최종 출력은 기존 9개 symptom이며, 외부 데이터와 상용 AI API는 사용하지 않습니다.
2. 모든 입력에 동일한 정책으로 256토큰 모델을 먼저 실행한 뒤, 전사 길이와 예측 불확실도로 일부만 512토큰 모델에 보내는 방식이 허용되나요? 라우팅 정책은 Training 내부 검증에서 고정하고 실제 라벨은 추론에 사용하지 않으며, 최종 클래스 판정은 모두 0.5로 유지합니다.

GPU 실행 보류 지시는 계속 유효하다. 규정 적합 판정은 GPU 실행 승인이나 제출 승인으로 간주하지 않는다.
