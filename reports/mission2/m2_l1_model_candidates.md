# Mission 2 L1: 53차원 피처 기준 모델 비교 후보

## 0. 미션 2 재정리

**과제**: 119 신고 통화 녹음에서 발화(utterance) 하나를 받아 화자가 **대원(0)**인지
**신고자(1)**인지 이진 분류.

**입력 제약 (대회 규정, 위반 시 실격)** — [[project-dcc2026-contest-rules]]:
- 분류 입력은 **그 발화 하나(`startAt`~`endAt`)뿐**. 같은 통화의 다른 발화 정보는
  순서 무관하게 전부 금지 (평균 길이, z-score 정규화, 화자 클러스터링 등 전부 포함).
- 발화 자신의 `duration_sec`은 허용(자기 자신의 속성이므로).
- PR #11에서 머지됐던 `call_relative` 피처(자기 통화 내 z-score)가 이 규정을 위반해서
  되돌려졌고, 지금 `gwanghee/mission2-feature-fixes-clean` 브랜치가 규정을 지키는 53차원
  버전이다. L2(CNN)는 스펙트로그램 자체를 쓰므로 이 제약과 무관 — 그대로 둔다.

**53차원 피처** (`mission2_features.py`, `feature-fixes-clean` 기준):
`duration_sec`(1) + MFCC mean/std(40) + RMS mean/std(2) + ZCR mean/std(2) +
spectral centroid/rolloff/bandwidth/flatness mean/std(8) = 53.
(pitch/energy 5종 + harmonicity 3종 + call-relative 3종, 총 11개는 PR #11에서 추가됐다가
규정 위반으로 되돌려졌다.)

**데이터 규모**: 전체 29,200통화, 889,358발화 (feature 추출 성공 826,333발화).
`call_id` 기준 `GroupShuffleSplit(seed=42, test_size=0.2)` — val 약 165,000발화.

**현재 L1 기준선** (`scripts/train_mission2_baseline.py`, LightGBM 기본 파라미터):

| 지표 | 값 |
|---|---|
| 전체 정확도 | **84.59%** |
| 대원 recall | 79.75% |
| 신고자 recall | 89.08% |
| 화자 격차 | **9.33%p** |

**오류 분석에서 이미 확인된 구조적 원인** (`m2_error_analysis.md`) — 모델을 바꾸는 것만으로는
못 고칠 가능성이 높은 것들:
1. **발화 겹침**: 오류의 57.3%가 여기서 발생, 대원·신고자 양쪽에 공평하게 손해 (화자 비대칭의
   원인은 아님) — 물리적으로 두 목소리가 섞인 오디오 자체의 문제.
2. **0.5~1초 구간이 최약체**: 전체 오류의 상당 부분을 차지. 대원 발화가 통계적으로 더 짧아서
   이 구간에 몰려있고, 모델이 "신고자"로 편향되게 찍는다.
3. **화자 비대칭은 데이터량과 무관**: 3,000→29,200통화(10배)로 늘려도 9%p대 격차가 그대로 —
   데이터 부족이 아니라 구조적 특성.
4. **오답도 확신에 차 있음** (오답 평균 confidence 67%) — threshold 보정으로 안 풀림, 실제
   threshold sweep에서도 최적값이 0.5 그대로 나왔다.

**따라서 이번 실험의 현실적 목표**: 모델을 바꿔서 84.59%를 큰 폭으로 뛰어넘길 기대는 낮게
잡되(위 1~4가 피처/데이터 레벨 문제라서), (a) 같은 피처로 LightGBM이 정말 최선인지 확인하고
(b) 화자 격차를 조금이라도 줄이는 모델/가중치 조합이 있는지 보는 것. L2 CNN(91%+)은 이미
별도 트랙으로 더 나으므로 L1은 "제출 후보"보다는 "피처의 실제 상한선 확인 + 대조군" 목적에
가깝다.

## 1. 모델 후보 비교

| 모델 | 장점 (Mission 2 맥락) | 단점 (Mission 2 맥락) |
|---|---|---|
| **LightGBM / HistGBM** (현재 기준선) | 53차원 연속형 통계 피처에 강함(비선형 상호작용, feature importance로 어떤 MFCC 차원이 기여하는지 바로 확인 가능). 826k 발화 규모에서도 학습이 빠름(분 단위). 이미 구현·검증됨. | 이미 이 피처로 84.59%에서 정체 — 트리 계열 안에서 더 좋은 모델을 찾아도 상한선 자체가 피처에 있다면 큰 개선은 어려움. 기본 파라미터만 쓴 상태라 데이터 규모(29,200통화)에 맞춘 재튜닝(트리 개수/깊이) 여지가 남아있음. |
| **Random Forest** | LightGBM과 다른 방식(배깅 vs 부스팅)으로 과적합에 더 안정적 — "부스팅이 이 피처에 과적합돼서 정체된 건 아닌지" 확인하는 대조군으로 유용. `class_weight='balanced'`로 대원 recall 가중 실험이 쉬움. | 트리 계열이라는 점에서 LightGBM과 근본적으로 다른 정보를 주진 않음 — 비슷한 상한선에 수렴할 가능성이 높고, 보통 부스팅보다 약간 낮은 성능. |
| **XGBoost / CatBoost** | LightGBM과 같은 부스팅 계열이지만 정규화·불균형 처리 기본값이 달라서(특히 CatBoost는 `class_weights`/`scale_pos_weight` 다루기 쉬움) 대원 recall 개선에 소폭 도움될 수 있음. | LightGBM과 사실상 같은 가설공간 — 비교 실험으로서의 한계 수익. 오픈소스 학습 도구라 대회 "모델 허용 규정"([[project-dcc2026-contest-rules]] — 커머셜 API 직접 호출만 금지) 위반 아님, 단 추가 의존성 관리 필요. |
| **로지스틱 회귀 (정규화)** | 빠르고 해석 가능 — "53차원이 선형 분리가 되는 문제인가"를 가장 값싸게 확인하는 sanity check. `class_weight='balanced'`로 대원 recall 실험 용이. | MFCC/스펙트럴 피처는 화자 간 비선형 상호작용이 일반적이라 트리 모델보다 낮은 성능이 거의 확실 — "최선의 모델"보다는 "하한선 기준점" 역할. |
| **SVM (RBF 커널)** | 비선형 경계를 학습할 수 있어 로지스틱보다 강한 대조군. 연속형 피처 53차원 규모에 원래 적합한 모델군. | **학습 826k / 검증 165k 발화 규모에서 커널 SVM은 O(n²)~O(n³)라 사실상 전량 학습이 비현실적** — 서브샘플링(예: 3,000~9,000통화 규모)으로 축소하거나 LinearSVC로 대체해야 함. 스케일링(StandardScaler) 필수. |
| **MLP (작은 feed-forward NN)** | 비선형 상호작용 학습 가능, class weighting/focal loss로 대원 recall 튜닝 여지 큼, 이미 L2 CNN 작업으로 GPU/PyTorch 파이프라인이 있어 재사용 가능. | 표 형태(tabular) 데이터에서는 트리 부스팅이 MLP를 이기는 경우가 많다는 것이 일반적 관측(53차원 통계 요약 피처는 전형적 tabular 데이터). 튜닝 비용 대비 기대 수익이 가장 불확실한 후보. |
| **나이브 베이즈 (Gaussian NB)** | 학습이 거의 즉시 끝나 최하한선 기준점으로 참고할 가치. | 53차원 피처 간 독립 가정이 명백히 깨짐(MFCC 계수끼리 상관 큼) — 후보라기보다 "이보다는 잘 나와야 정상"인 바닥선. |
| **스태킹/투표 앙상블** (LightGBM + RF + MLP 등) | 개별 모델이 서로 다른 오류를 만든다면 앙상블로 소폭(1~2%p) 개선 가능 — 특히 화자 격차처럼 특정 구간에서만 갈리는 오류는 앙상블이 완화하는 경우가 있음. | 개별 모델 비교가 끝난 뒤에나 의미 있음(재료 없이 앙상블부터 하면 원인 파악이 안 됨). validation split에 과적합해서 튜닝하는 리스크 — 최종 판단은 별도 holdout이나 반복 seed로 검증 필요. |

## 2. 권장 실행 순서

1. **로지스틱 회귀 + Gaussian NB** — 각각 하한선/선형성 기준점을 빠르게 확보 (수 분 내).
2. **Random Forest** — LightGBM과 같은 트리 계열 대조군, `class_weight='balanced'` 옵션도 같이.
3. **XGBoost 또는 CatBoost** — LightGBM 대비 소폭 개선 여지 확인, 특히 대원 recall.
4. **(선택) SVM** — 3,000~9,000통화 서브샘플로 축소해서 "비선형 경계가 실제로 도움되는가"만
   빠르게 확인 (전량 학습은 비현실적).
5. **(선택) MLP** — 위 결과에서 트리 계열이 이미 상한선에 도달했다는 게 보이면 우선순위 낮춤.
6. 모든 모델에 **같은 GroupShuffleSplit(seed=42) 재사용** — L1 기준선(84.59%)과 직접 비교 가능해야
   의미 있음. 정확도뿐 아니라 **대원/신고자 recall과 격차(9.33%p)를 항상 같이 보고** — 정확도만
   보면 격차를 숨기는 모델(다수 클래스 쏠림)을 놓칠 수 있음.
7. 마지막에만 상위 2~3개로 스태킹/투표 앙상블 시도.
