# M2-CNN-006 — duration-conditioning(SpeakerCNNLargeWithDuration) seed 통제 재검증

## 배경

M2-CNN-004(2026-09-16)에서 `SpeakerCNNLargeWithDuration`(발화 자신의 `duration_sec`을
classifier head에 명시 입력)이 전체 정확도 +0.30%p, 대원/신고자 recall 격차 확대(8.45%p→
9.17~9.35%p)로 측정돼 "격차를 못 줄인다"는 이유로 기각됐다. 그런데 이 측정은 `--seed`가
train/val 분할에만 쓰이고 모델 초기화·`DataLoader` shuffle 순서는 통제되지 않은 1회 실행
결과였다. `collate_batch`는 배치마다 그 배치의 최장 발화 길이로 padding하므로, shuffle
순서가 다르면 짧은 발화가 어떤 발화들과 한 배치에 묶이는지도 달라진다 — M2-CNN-005(hop80
pilot)가 20에포크→35에포크 사이에 부호가 통째로 뒤집힌 것과 같은 종류의 confound다.

이번 재검증은 두 가지를 분리했다:
- `scripts/train_mission2_cnn.py`에 `--torch-seed`를 추가(모델 초기화 + train shuffle 순서).
  `--seed`(=42, train/val 분할)는 모든 실행에서 고정해 같은 held-out set을 유지.
- `--torch-seed`를 1/2/3으로 바꿔가며 `large`/`large-duration`을 각각 학습, 같은 torch-seed의
  두 모델은 shuffle 순서가 동일(같은 generator seed)하므로 배치 구성 confound가 쌍 안에서는
  제거된다.

판정 기준은 실행 전에 고정: 전체 accuracy 기준으로 3개 seed 전부 양수이고 평균 +0.5%p 이상이면
가설 지지(Phase B 진행), 부호가 갈리거나 평균 |차이| < 0.5%p면 잡음으로 종료.

## 설정

- 표본: 3,000통화 pilot(M2-CNN-005와 동일 표본, split seed=42).
- 모델: `SpeakerCNNLarge` vs `SpeakerCNNLargeWithDuration`, 각 35에포크(20 + `--resume` 15).
- torch-seed: 1, 2, 3 (모델 초기화 + train shuffle 순서만 변경, held-out set은 불변).
- 평가: 같은 held-out set(18,134발화)에서 duration bucket별 정확도.

## 해석

- **전체 accuracy: 3개 seed 전부 음수(0/3), 평균 -0.15%p.** 판정 기준(전부 양수 & 평균
  ≥+0.5%p)에 못 미치고, 사전 기준상 "평균 |차이| < 0.5%p면 잡음으로 종료"에 해당한다.
  평균 -0.15%p는 같은 모델의 seed 간 noise 기준선(0.15~0.17%p)과 비슷한 크기라서, 여기서
  말할 수 있는 것은 "M2-CNN-004의 +0.30%p가 재현되지 않는다"까지다. 발화 길이 입력이 전체
  성능을 나쁘게 만든다는 확정은 아니다.
- **[탐색적 관찰 — 사전 판정 기준에 없던 항목, n=3] 가설이 정확히 겨냥했던 0.5-1s 버킷도 3개
  seed 전부 음수(0/3), 평균 -0.70%p** — 이 폭은 같은 모델의 seed 간 noise 기준선
  (~0.15~0.17%p)보다 크고 방향도 일관돼서, 우연한 산포보다는 실제 효과(duration 입력이 이
  버킷에 오히려 해가 됨)일 가능성이 있다. 다만 n=3이고 미리 정한 판정 대상이 아니라서
  확정하기는 이르다.
- **<0.5s 버킷은 부호가 갈림(+0.51, -0.51, +0.83)** — 신호 없음, 판단 보류.
- M2-CNN-005(hop80)와 비슷한 교훈: 둘 다 "seed/배치 순서를 통제하지 않은 1회 실행은 노이즈를
  신호로 오인하게 만들 수 있다"는 것을 보여준다. 다만 hop80은 seed를 통제해서 다시 확인한
  적이 없으므로, 이번 결과가 hop80 효과의 유무를 알려주지는 않는다.

## 재현 조건 메모 (2026-09-28, PR #31 리뷰 반영)

같은 조건(3,000통화 pilot, split seed 42, `SpeakerCNNLarge`, torch-seed 1/2/3, 35에포크)이라고
적은 이 보고서의 `large` 기준선 정확도가 `m2_cnn_nmels_seed_recheck.md`의 `n_mels=40` 기준선과
seed마다 조금 다르다.

| torch_seed | 이 보고서의 `large` | nmels 보고서의 `n_mels=40` | 차이 |
|---|---|---|---|
| 1 | 0.8904 | 0.8888 | +0.16%p |
| 2 | 0.8876 | 0.8863 | +0.13%p |
| 3 | 0.8874 | 0.8888 | -0.14%p |

- **확인된 것**: 두 실험은 서로 다른 Colab 세션에서 따로 실행됐다(각 Colab 스크립트가 세션마다
  3,000통화를 다시 추출하고 스펙트로그램을 새로 만든다). 코드 버전도 달랐다 — 이 실험은
  `--torch-seed` 커밋(`86a4696`) 시점, nmels 실험은 `--n-mels` 커밋(`64b1b22`) 이후. 학습
  코드는 `--torch-seed`로 모델 초기값·셔플 순서를 고정하지만, GPU 연산의 비결정성(cuDNN 등)을
  따로 고정하지는 않는다.
- **확인 못 한 것**: 위 차이의 실제 원인(세션별 스펙트로그램 재생성, GPU 비결정성, 코드 버전
  차이, 중간에 끊겨 `--resume`으로 이어붙였는지 여부 등). 이어붙이면 셔플 순서가 첫 에폭 순서부터
  다시 시작된다(Colab 스크립트 주석). 사용한 체크포인트는 Google Drive에 있고 이 저장소에는 없다.
- **설정 표기 확인 필요**: 위 "설정"의 "35에포크(20 + `--resume` 15)"는 M2-CNN-005 때와 같은
  표기인데, 이 실험의 Colab 스크립트(`M2_Colab_L2_duration_재검증_스크립트.py`, DCC 루트, git
  미포함)는 35에포크를 한 번에 돌리고 끊겼을 때만 `--resume`으로 이어가게 되어 있다. 실제로
  어떻게 돌렸는지는 기록이 없다.
- **의미**: 기준선 차이(0.13~0.16%p)가 seed 간 편차(0.15~0.17%p)와 비슷한 크기라서, `--torch-seed`만으로는
  GPU 학습이 완전히 재현되지 않는 것으로 보인다. 그래서 이 보고서의 판단은 같은 세션·같은
  스펙트로그램·같은 torch-seed로 학습한 두 모델의 짝 비교에만 의존하고, 보고서 사이의 절대
  정확도는 비교하지 않는다. 0.15%p 안팎의 작은 차이는 이 방식으로 구분하기 어렵다.

## 결론 및 후속

**기각(채택하지 않음).** `SpeakerCNNLargeWithDuration`을 채택하지 않는다. M2-CNN-004의
+0.30%p는 재현되지 않았으므로 개선 근거로 쓰지 않는다. 짧은 발화(0.5~1초 backchannel)
병목에는 다른 메커니즘(예: `n_mels` 확대, duration bucket 가중 샘플링)을 다음 후보로 검토한다
(`n_mels` 확대는 이후 M2-CNN-007에서 시험했고 채택 근거를 못 얻었다). `--torch-seed`는 앞으로 이런 A/B 비교의 기본
절차로 유지한다.
